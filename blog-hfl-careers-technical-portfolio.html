Build a Technical Portfolio That Shows What You Can Do

A practical checklist for candidates exploring HFL careers in software, AI, testing, cloud, product and research—and role areas connected to HFL Astra’s space-technology roadmap.

Open the official HFL Careers page →

A useful technical portfolio is not a list of tools or course certificates. It is a set of examples that help another person understand your contribution, the problem you addressed, how your solution behaves and what evidence supports your claims. One complete, well-documented project is often easier to evaluate than many unfinished demonstrations.

First, a note about vacancies: HFL’s careers pages describe role families and application routes. A role area is not, by itself, confirmation that a specific job is currently open. Check the HFL Tech careers page or HFL Astra role areas and wait for the team to confirm the position and its terms.

1. The six pieces every project write-up should contain

  • Problem: who the project is for, what it attempts to solve and the constraints you considered.
  • Your contribution: what you personally designed, coded, tested or documented—especially when working in a team.
  • Architecture: a simple diagram and an explanation of the main components and data flow.
  • Reproducibility: setup instructions, dependencies, a sample input and expected output.
  • Evidence: tests, evaluation criteria, screenshots or a short demo that show how the result behaves.
  • Reflection: trade-offs, limitations, bugs found and what you would improve next.

2. Make the evidence fit the role

Role areaUseful evidence to show
Software engineeringA small deployed application or API, clear code structure, tests, setup instructions and a concise explanation of design decisions.
AI systems and agentsA reproducible demo, an evaluation set, error cases, tool permissions, failure handling and a clear account of where human review is required.
QA and testingTest cases linked to requirements, useful bug reports, automated checks and an explanation of what the tests do not cover.
Cloud, DevOps and securityA deployment diagram, automated checks, logs and monitoring examples, least-privilege choices and a safe description of the threat model.
Product and UXA problem statement, a few user flows, accessible interaction states, prototypes and a short account of the feedback that changed the design.
HFL Astra-related software or researchA documented orbit or mission-planning simulation, telemetry visualisation using clearly labelled sample data, requirements analysis, technical literature review or a model with stated assumptions and limits.

3. For space-system pathways, start with safe and testable work

Early-career candidates can build relevant evidence without claiming flight hardware or conducting hazardous experiments. Software-level projects could include a visualisation of orbital parameters, a telemetry dashboard using generated data, a requirements-traceability table, a simple mission timeline tool or a simulation that states its mathematical assumptions. Explain the limits of the model and compare outputs against trusted reference cases where possible.

For aerospace, propulsion, communications or guidance-related research, a literature review can be valuable when it identifies the question, compares credible sources, defines terminology, records assumptions and explains uncertainty. Do not present a concept diagram or simulation animation as proof of an operational system.

4. Make a GitHub repository easy to review

  • Write a README with the purpose, prerequisites, installation steps and a short demo.
  • Keep secrets, API keys, private data and credentials out of source control.
  • Use meaningful commit history, consistent naming and sensible error handling.
  • Include tests or a clear manual test plan, plus known limitations.
  • Link to a working demo when available, and state when it is a prototype or school project.

5. Write a concise application note

Use a clear subject naming the role area, then explain in a few sentences why the area interests you and which example best demonstrates your skills. Attach or link your CV and the most relevant work. State availability and preferred engagement type where appropriate. Do not send passwords, one-time codes, payment details or private credentials.

Never pay an application fee. If a message asks for money, credentials or sensitive information in exchange for recruitment, verify it through an official HFL contact route before taking any action.
